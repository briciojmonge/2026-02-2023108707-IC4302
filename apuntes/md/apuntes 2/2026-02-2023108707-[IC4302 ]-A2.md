## RAID 0

Los sistemas RAID 0 dividen los datos entre varios discos. Esto aumenta aumentan la velocidad de escritura, pues los los datos son escritos en paralelo en los distintos discos. El problema principal con este sistema es que si se daña 1 disco se pierden los datos. En este sistema la búsqueda se realiza en paralelo. Y finalmente, se puede decir que este sistema mejora los IOPS (combinando los discos). Ej: Si cada disco = 500 GB → O.S. ve 1 TB

## RAID 1

RAID 1 es otro sistema común de replicación y se cosidera la forma más común de replicar, en este caso, en vez de dividir datos copia los mismos datos a todos los discos, enviando datos iguales a los discos. La escritura se mantiene en la cantidad de IOPS del disco "master". En cambio, la lectura sí añade IOPS de los discos extra. EJ. Teniendo 2 discos de 500 GB y de 200 IOPS. En O.S. se vería 1 disco de 500 GB, y los IOPS serían write: 200 IOPS, Read: 400 IOPS.

![RAID-1](https://thumb.wikimedia.org/wikipedia/commons/thumb/b/b7/RAID_1.svg/330px-RAID_1.svg.png?utm_source=en.wikipedia.org&utm_campaign=parser&utm_content=thumbnail)

![RAID-lectura](<images/RAID-lectura.png>)

Cuando se dice que la lectura incrementa es porque si se pide una cantidad de datos muy grande, El RAID Controller genera sistemas de bloques de cierto tamaño y de una cierta cantidad de megas, y los discos se encargan de llenar un bloque de datos cada uno, cuando los discos terminan de entregar los bloques, se devuelven los datos al RAID Controller, el cual los envía a O.S., y se llenan los próximos bloques.
*Nota*: Existen RAID Controllers desarrollados en Software y otros manejados por Hardware.

## Bit Paridad

![BP 1](<images/BP 1.png>)

El bit de Paridad es un sistema de seguridad para datos que permite recuperar los datos de un disco perdido mediante el calculo de la cantidad de 1s por byte de los discos, estas deben ser pares, si el disco de paridad tiene un 1 eso significa que los 1s no eran pares. Se menciona que si se pierde más de un disco es difícil o imposible recuperar los datos.

Por ejemplo, si se tiene:  1011 (100GB) | 0111 (100GB) | 1100 (Paridad). Pero, se puede decir que tiene 2/3 de uso de disco para datos. puesto que puede usar los dos primeros discos para leer y escribir pero el 3ero funciona solo para añadir los digitos de paridad o leer en caso de fallo en 1 disco.

![BP 2](<images/BP 2.png>)

### En RAID 1

![enraid1](<images/enraid1.png>)

- Si se pierde un disco se sigue teniendo los datos en los demás; se pueden perder varios, lo que cae son los IOPS → de 600 IOPS → 400 IOPS
- En cambio, utilizando el bit de pariedad: Si se pierde 1 disco, la paridad se utiliza para reconstruir los datos, pues la cantidad de 1s debe ser par.
- Para añadir un disco el sistema debe volver a reconstruir los datos para añadirlos al nuevo. Se pierde rendimiento porque cada lectura debe reconstruir los datos.

![raid+pariedad](<images/raid+pariedad.png>)

![bandwidth](<images/bandwidth.png>)

### RAID 5: Block Level

Igual a la 4, pero la paridad se va alternando entre bloques. Por lo que si se pierden los datos, en el RAID 5 se reduce la cantidad de bloques a las que se les debe calcular, y se vuelve un 25% más rápido.

También se puede reconstruir discos mediante XOR.

- Se vuelve más rápido reconstruir datos a partir de XOR.

Ejemplo:

| | Disk 1 | Disk 2 | Disk 3 | Disk 4 |
| --- | --- | --- | --- | --- |
| Stripe 1 | 0100 | 0101 | 0010 | 0010 (Paridad) |
| Stripe 2 | 0010 | 0000 | 0110 (Paridad) | 0100 |
| Stripe 3 | 0011 | 0001 (Paridad) | 1010 | 1000 |
| Stripe 4 | 0110 (Paridad) | 0001 | 1101 | 1010 |

- Paridad: 0100, 0101, 0010

## RAIDs anidados

### RAID 10

- RAID 0 → RAID 1, RAID 1

- En este sistema anidado se envían sets de datos diferentes mediante el RAID 0, y se copian a dos discos de cada RAID 1. Esto se hace para que si se fueran a perder los datos, se deben perder todos los discos dentro de uno de los RAID 1.

![RAID-10](https://thumb.wikimedia.org/wikipedia/commons/thumb/e/e6/RAID_10_01.svg/500px-RAID_10_01.svg.png?utm_source=en.wikipedia.org&utm_campaign=parser&utm_content=thumbnail)

## Clasificación de Datos

### Batch

![batch](<images/batch.png>)

- La información de Batch es finita, tiene un inicio y un final, está almacenada y no cambia. Está almacenada en un disco server side.
- Los datos o archivos en batch se almacenan en un disco con modalidad server-side
- Además estos datos cuentan con una encriptación denominada: "at rest".

### Streaming

A los datos en streaming se les llama "In transit" o "On the fly" pues se transmite mediante red. Es "infinito", la llegada de información es constante. No de una manera real, se considera infinito ya que se refiere a que no se sabe cuando terminan de llegar datos. Al igual que los datos en Batch, estos datos deben de ser encriptados. En terminos de observabilidad, si se realizan análisis al streaming, los datos son fluctuantes, ya que llega información diferente cada cierto tiempo; el batch genera análisis constantes.

![stream](<images/stream.png>)

## Windows de monitoreo

- Hablando un poco de las ventanas para los sistemas de monitoreo, se pueden generar windows/ventanas que funcionan para analizar los datos streaming.
- Estas ventanas son "cuadros" que revisan un sector de datos que está en Streaming, de modo que los datos fluyan en esa ventana.
- Se puede decir que las ventanas de monitoreo intentan tomar los datos del streaming para verlos como batches.
- Existen dos tipos de windows.

![ventanas](<images/ventanas.png>)

### Ventanas

#### Fixed

- Puede ser por tiempo  
- Puede ser por tamaño de datos  
- Puede ser por cantidad de eventos  

#### Sliding time

- Se toman los datos de una sección de los datos en un punto del tiempo, y después se corre la ventana para tomar otros datos en otro punto del tiempo.
