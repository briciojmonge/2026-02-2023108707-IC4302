**Optimización de consultas:** 
Los motores de bases de datos analizan las consultas, validan las sintaxis, las tablas y las columnas. Se generan "planes de ejecución", son secuencias de pasos a realizar según lo necesitado, y se relacionan directamente con la optimización de queries. De modo que es un punto importante ya que los planes de ejecución deciden como se leen los datos.
**Índices:**
Los indices permiten busquedas más rápidas convierten un scan en un seek.Aunque estos ocupan de disco y deben actualizarse con cada acción como inserciones, updates y deletes. Tener demasiados indices puede frenar a las  escrituras y sobreindexar hace las lecturas más lentas.
**Bloqueos y concurrencia:** 
Las bases hacen uso de locks para garantizar atomicidad. De modo que si las transacciones no terminan, las demás quedan bloqueadas. Se busca que las transacciones sean cortas para reducir bloqueos y mejorar concurrencias
**Memoria, caches y concesiones de memoria para consultas:**
Los motores usan memoria para varios caches, se utiliza para caches de buffer, de planes y de resultados, y buffers de logs. Se hace la asignación para ordenamientos joins, y operaciones. Por lo que, si se configuran mal las bases o hay estadísticas pobres se debe revisar la optimización de este aspecto. 
**Alamcenamiento, I/O y log de transacciones:**
Las bases tienen cargas intensas de I/O. se necesita de almacenamiento rápido y de baja latencia para poder encargarse de las consultas que no están en caché, y para cumplir con ACID se debe escribir cada transacción dentro de un log.

3. Un Anti-pattern es una forma inefectiva de resolver un problema. Son patrones de consulta o diseño que generan mal rendimiento,bloqueos, exceso de I/o y poca escalabilidad. Se menciona el procesar los datos fila por fila con loops o cursores, en vez de procesar por conjuntos, usar "SELECT *" en vez de solo usar las columnas especificas, tipos de datos inconsistentes, etc.
