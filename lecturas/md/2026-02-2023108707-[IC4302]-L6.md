### Respuestas

1.`Explique la arquitectura de Cassandra, puede apoyar su respuesta con otros recursos.`

- Cassandra es un sistema de bases de datos NoSQL que escala masivamente de forma muy sencilla. Cuenta con una arquitectura Peer-to-peer entre varias pcs con nodos, dónde cada nodo es igual, por lo que no se cuenta con un Master. A raiz de no contar con una estructura master-slave, no cuenta con un punto único de fallo, y se dice que tiene disponibilidad continua.
- Distribuye los datos en una red de nodos con forma de anillo, se distribuye automáticamente, y se particiona de manera ordenada o aleatorea, con un valor aleatoreo por defecto. En el ámbito de réplicas, cuenta con una integración propia hacia estas de modo que son configurables desde la base, definiendo la cantidad de replicas a manejar.
- Además, Cassandra permite replicar datos a través de varios centros de datos o varias plataformas de nube. Y un solo Cluster de Cassandra puede tener a varios data centers o tener un diseño híbrido. Cuando se crean los Keyspaces se puede indicar que data centers o proveedores mantendrán las bases.
- La escritura dentro de  Cassandra funciona de manera diferente a otros sistemas dónde se escribe a una sola base, las bases de datos en los nodos pueden ser leídas y escritas en cualquier momento, de manera que si hay nodos caidos se puede redirigir el sistema hacia otro nodo. En el caso de las lecturas, estas funciona de manera paralela, mediante un nodo coordinador, se genera la consulta desde uno o más notos que contienen los datos.

2.`¿Cómo funciona la replicación de Cassandra? ¿Cómo se diferencia de un esquema Master-Slave?`

- Cassandra cuenta con replicas redundantes en los nodos de la red con forma de anillo, de manera que si cae un nodo hayan copias en los demás nodos. Además estas replicaciones se pueden configurar de manera sencilla dentro de Cassandra, dentro de esta se define el número de copias a mantener y el sistema de Cassandra administra lo demás. Añadido a la facilidad de configuración, también se añade la opción de poder hacer replicaciones en diferentes racks, datacenters o nubes.
- El sistema de Cassandra se diferencia de los esquemas Master-Slave, en que Cassandra funciona como peer-to-peer, sin utilizar de un nodo como Master y sin tener un punto único de falla, a diferencia de las bases Master-Slave las cuales si tienen este punto único de falla.

3.`¿Cómo afecta el modelo de replicación y de escritura la consistencia de datos?`

- La consistencia de datos en Cassandra es ajustable por operación (SELECT, INSERT, UPDATE, DELETE), y se puede elegir si debe ser fuerte, que se refiere a que todos los nodos responden, o eventual, dónde solo uno responde y los otros eventualmente responden. Se podría configurar para que los datos críticos utilizen todos los nodos y los menos críticos son eventuales. Además, el sistema de Cassandra acepta el uso de uno o varios data centers para la configuración de consistencia de datos. Aún así, el nivel de cosistencia afecta a la latencia y disponibilidad, un nivel más fuerte requiere de que más nodos respondan y uno evental de menos.
- En el ámbito de la escritura, cuando un nodo se encuentra fuera de servicio, se puede escribir a otro nodo de manera temporal, y cuando se reemplaza el nodo fuera de servicio, se actualizan los datos. Por otro lado, en la parte de lectura, cuando un nodo está fuera de sercicio, se lee de alguna de las réplicas de las bases.
