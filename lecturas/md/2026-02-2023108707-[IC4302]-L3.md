#### Preguntas:

1.       En términos simples, ¿cuál es la principal diferencia entre las consultas en una base de datos de vectores y bases de datos relacionales?

2.       ¿Cómo se diferencia la representación de datos en una base de datos de vectores con bases de datos SQL y NoSQL?

3.       ¿Qué es un vector embedding o feature vector?

4.       Explique el concepto de similarity search.

5.       Explique los diferentes use cases para los que se pueden utilizar bases de datos de vectores.
____________________________________________

## Respuestas:

1. La principal diferencia entre las consultas de bases de datos basadas en vectores y las bases de datos relacionales es que en las bases de datos de vectores se generan querys a partir buscar vectores similares a otros vectores dados.

2. Las bases de datos SQL y NoSQL normalmente se nfocan en datos almacenados con una estructura como key-value que guarda un identificador por cada dato o sección de datos (estructurada o no) o como una base de datos por celdas o columnas. Pero, las bases de datos vectoriales guardan y representan datos mediante un conjunto de vectores, osea, un grupo de números en representación del acercamiento a ciertos parametros o a ciertas dimensiones.

3. El vector embedding o feature vector es el resultado y proceso de pasar un conjunto de datos a una representación vectorial, de modo que las dimensiones del vector resultante puedan guardar relación con los datos o patrones.

4. El concepto de similarity search se refiere las busquedas en bases de datos vectoriales, realizadas mediante queries que pueden utilizar uno o varios vectores como referencia para calcular los vectores más cercanos o parecidos dentro de la base. Se utilizan calculos como distancia Euclidiana, similaridad de Jaccard, producto punto y similaridad de cosenos.
